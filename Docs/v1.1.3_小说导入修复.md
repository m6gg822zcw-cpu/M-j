# v1.1.3 · 小说导入修复

版本 1.1.3，build 5，2026-10-25。

## 已复现的问题与修改

- 旧默认章节正则允许标题空白匹配换行，导致 `序章\n林舟走进书店。` 把正文吃进标题，报“仅找到章标题，没有正文”；多段时会丢掉首段。标题空白现在限制为水平空白，保留实际正文与原文位移。
- EPUB、DOCX 原来按 XML 标签的字面前缀读取，合法的 ocf/opf 或 ns0 Word 文档可能报缺阅读顺序、没有正文。现在按命名空间 URI 和本地名称识别，保留常见前缀、无命名空间旧 EPUB、Strict Word 与外部实体禁用行为。
- 系统文档入口仅登记 MOXU。现为 TXT、Markdown、JSON、EPUB、DOCX、PDF 登记 Viewer / Alternate，不抢占系统默认打开程序；外部文件冷启动时等待同一个初始化任务。
- 书架使用系统 SwiftUI 文件导入器，接受通用文件后按扩展名校验；选中回调直接调用实际导入方法，不依赖关闭弹层时读取临时 State。持有 security scope，在后台协调读取并受限复制为临时副本，源文件不修改。用户取消选择不触发导入；已选文件的读取若被提供器中断，会明确提示重新下载。
- 书架页脚显示实际版本号，方便确认安装版本。作品和书稿副本保留在 App 私有目录；从“文件”App 的外部位置选择小说。

## 验证

Linux Swift 6.0.3 全套 95 项核心测试通过，新增 8 项章节标题与 XML 命名空间回归。真实 iOS 编译、系统文件选择器 UI 测试及更新 IPA 正在验证。

UI 测试仅在 DEBUG 的显式参数下准备 TXT/JSON 测试文稿，不调用导入方法。测试由 Simulator host 将公开测试文稿复制到“文件”App 的本地下载目录，须真实点击书架按钮、进入系统选择器选中外部文件、观察成功反馈及书架条目、取消后重开；脚本再核对实际工程正文和源文件字节。原有 9 项本地导入/漫画导出检查保留。

## 验证边界

用户尚未提供失败文件、来源或错误原文，不能断言以上复现与其设备上的原因完全相同。测试不覆盖真实 iCloud/第三方云盘账户授权、未下载文件与实际签名设备；扫描 PDF 仍需 OCR，DRM 书籍不解密。自定义章标题正则仍按用户配置执行，错误规则不会静默改写。未调用真实收费 API，NAI 请求格式与每页 1/2/4 格排版保留。

交付 IPA 在缺少 Apple 签名材料时明确为 unsigned，需要签名后安装。
