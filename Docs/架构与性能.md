# 架构与性能

界面使用 SwiftUI 原生控件与系统导航。纸张色、朱砂强调色与深青辅助色统一在 `Ink`；适配系统深色模式，不依赖嵌入网页。

## 线程与内存

`StudioModel` 在 MainActor 上发布轻量状态，队列一次执行一个工作任务。`Repository`、`Pipeline`、`ProviderClient`、`AssetProcessor`、`BitmapCache`、`ComicExporter` 使用 actor 分离文件、请求、解码与排版。文件导入放到 detached task，避免在主线程解析整本 EPUB 或 PDF。

阅读使用 LazyVStack / LazyVGrid，图片用 ImageIO 按显示像素缩小并提前解码。缓存限制 40 张、约 48MB，收到系统内存警告清空；不一次加载全书全部位图。参考图先缩放，多个参考超过平台上限时在本机生成编号对照板。图片输出最大规范化到 3072px，避免把超大原图直接用于滚动列表。

导出按页解码和绘制，PNG 逐页写盘，ZIP 流式读取每个文件，HTML 逐页写入嵌入图片。大型作品仍可能受到设备内存、磁盘与系统时间限制，需要真机 Instruments 验证；这些设计不等同已测得具体帧率。

## 文件与恢复

作品单独放在 `Application Support/Moxu/Projects/<UUID>`，目录保存：

- `Project.json`：章节索引、人物、外观冲突与关系。
- `Chapters/N-source.json`：该章原文段落和 UTF-16 位移。
- `Chapters/N-run.json`：完成批次、分镜、融合记忆、结尾连续性。
- `Images/<UUID>.png`：定妆与漫画图片；新图使用新文件名，旧图不会被覆盖。
- `Receipts/N.json`：收费图片请求的未完成凭据。

分镜与人物变更通过同一 `Journal.json` 事务先写入，再原子替换分镜和工程清单。重新列出书架时恢复未完成事务。图片请求则先落凭据、再发请求，原始响应先保存，最后提交清单并清理凭据。

备份只装入作品、原文、图片与当前画师方案，不包含全局连接配置、Keychain 密钥或队列。在另一台设备恢复时创建新的作品编号；若同编号画师方案内容已改变，导入副本保留备份画风。

## 人物与服装

身份层与服装层分别建模。原文明示的新年龄 / 变身阶段使用新角色编号，通过 lineageID 关联原人物。后续冲突先写入冲突列表；文本模型不能直接覆盖锁定脸。

服装可脱部件的英文标签按六层存储。画格只指定服装 key 与本格状态，组合器读取锁定衣装并去掉 removed 层。中文动作、持物与伤势进入固定事实 JSON，NAI 的动作英文串独立，不允许用姿势标签重设整个人。

## 后台

使用系统有限后台时间完成当前请求与保存，不伪装持续后台工作。进入后台会暂停后续任务；系统到期时取消本机等待。重新启动把运行中 / 排队中的任务恢复为暂停，等待用户继续。由于服务可能在本机取消后仍继续生成，未完成凭据必须先核实，不能自动补发图片。

## 扩展

新增服务至少补齐请求构造、返回解析、鉴权方式与异常语义，最好使用注入的 `HTTPTransport` 编写固定响应测试。现有 `URLTransport` 从临时下载文件读取响应，限制单次响应 64MB。项目不内置服务代理，也不保存或上传到开发者自建云。

## v1.1 手工排版

新增独立的 ComicLettering，坐标只相对于原图，不依赖屏幕与分页留白。UIKit 的 BubblePainter 同时供原生阅读、编辑、全屏合成预览和导出调用，使用同一文字测量与尾巴路径。保存只改分镜的 lettering 字段，原图与原对白保持不变；流水线提交保留磁盘上的较新排版。
